# Jenny Hoang, research portfolio

A bilingual (English / Tiếng Việt) research portfolio. Plain HTML and CSS generated by one small Node script, with no framework and no dependencies, so it is easy to read, edit and host anywhere.

- English pages: `/en/…` · Vietnamese pages: `/vi/…`
- The site root (`/index.html`) sends visitors to the language they used last, or to their browser language, or to English.
- The EN/VI switch on every page opens the same page in the other language.

> **Versions.** This branch (`pflo2`) holds **PFLO2 "Issue 01"**, an experimental editorial design. The frozen baseline **PFLO1** (v4 "Dawn") is the tag `pflo1` on `main`. See `docs/PORTFOLIO_VERSION_MANIFEST.md` for hashes and restore commands, and `docs/PFLO2_DESIGN_BRIEF.md` for the concept, blueprint and design system.

## Requirements

Node.js 18 or newer. Nothing to install.

## Commands

| Command | What it does |
| --- | --- |
| `node build.mjs` | Builds the full site into `dist/` (includes CV PDFs from `public/cv/`). |
| `node build.mjs --artifact` | Builds a preview into `dist-artifact/` with PDF download links turned off. |
| `node scripts/check.mjs dist` | Checks every internal link and `#anchor`, the `lang` attribute, and that EN and VI pages have the same sections. Exits with an error if anything is wrong. |
| `npx serve dist` | Serves the built site locally at http://localhost:3000 (or open `dist/index.html` directly). |

## Project structure


## How PFLO2 is organised

The site reads as one issue of a publication. The cover page (`index.html`) holds the cover, the contents, chapter 01 (opening note) and chapter 02 (features). Every other page is a chapter with a numbered opener: 03 The index (`projects`), 04 Field notes (`activities`), 05 Chronology (`about`), 06 Method (`approach`), 07 Notebook (`notes`), 08 Writing, 09 CV, 10 Colophon and contact. Chapter order lives in `CHAPTERS` in `build.mjs`; chapter titles and one-line descriptions live in `content/issue.mjs` under `chap`.

- The cover is built by `issuePage()` in `build.mjs` from `content/issue.mjs` and `content/projects.mjs`. The `index` entries in `content/en.mjs` and `content/vi.mjs` are no longer used.
- **Features** are the projects that have a `page`. They are listed in the order of `sort` (newest first) and get a feature opener (plate, caption, credits strip) and a previous/next pager.
- **The index** shows every project four ways: by year, by theme, by kind, and as a theme map. Themes are set per project (`theme`: `evidence`, `trade`, `rights` or `tools`) and named in `content/issue.mjs` under `themes`.
- To add a chapter: add its key to `CHAPTERS`, a page entry in both language files, a `chap` entry in both halves of `content/issue.mjs`, and a hue in `CH_HUE`.

## Editing content

Page text lives in `content/en.mjs` and `content/vi.mjs`. Each page (`index`, `projects`, `activities`, `about`, `approach`, `notes`, `writing`, `contact`, and one page per project: `cisg`, `jcj`, `hs61`, `ds92`, `drivers`, `admin`) has a `title`, a `desc` (search results and link previews) and a `body`.

Helpers available inside a body:

- `h.block(id, title, intro, body, tint)`: a full-width home section with a large heading (`tint` = `"blue"`, `"peach"` or empty).
- `h.sec(id, title, main, margin)` and `h.wsec(...)`: a reading section with an optional side note.
- `h.note("", html)`: a short side note (sources, caveats). Do not use it for internal reminders.
- `h.gallery()`: the home project cards (projects with `home: true`). `h.archive()`: all projects with filters.
- `h.caseHero({ id, kicker, title, lede, meta })` and `h.caseBody(toc, sections)`: a project detail page.
- `h.actList(group)`, `h.actPreview([ids])`, `h.phases(...)`, `h.timeline(...)`, `h.table(head, rows)`, `h.link(slug, text)`, `h.go(href, text)`, `h.btn(href, text)`.

**Rules for both languages**

- Keep the same section `id`s in EN and VI. The checker fails if they differ.
- No en dash or em dash anywhere. Use "to", a comma, a colon or parentheses. For Vietnamese school years a hyphen is fine (2024-2025). The checker fails on any dash in the built pages.
- The public site carries no internal notes (verification status, "to be added", drafts). If a fact is not confirmed, leave it out until it is.
- The brand is Jenny Hoang. The full name appears once, on the About page, and on the CV.

## Adding a project

1. Add an entry to `content/projects.mjs` (copy an existing one) and fill `en` and `vi`, including `alt` text for its picture.
   - `no`: the next catalogue number. `type`: `research`, `coursework`, `technology` or `ongoing`.
   - `theme`: `evidence`, `trade`, `rights` or `tools` (used by the index and the theme map). `home` is not used in PFLO2.
   - `page`: a detail-page slug, or `link` to point somewhere else.
2. Give it a hue in `HUE` (build.mjs) and add its artwork: write a scene in `scripts/art.mjs` (add its sky to `SKY`) and run `node scripts/art.mjs`, or put your own image at `assets/art/<id>.svg` (or change the card to a .jpg) and record it in `assets/art/README.md`.
3. If it has a detail page, add a `<slug>` entry to both language files using `h.caseHero` and `h.caseBody` (copy `hs61`). `build.mjs` picks up the page from `projects.mjs` and adds it to the features, the contents and the cover lines.
4. `node build.mjs && node scripts/check.mjs dist`.

## Adding an activity

Add an entry to `content/activities.mjs` with `group`: `work`, `lead`, `debate`, `school` or `recognition`, and both languages. It appears in chapter 04 (Field notes) in date order.

## Updating the resumes

The Harvard-style resumes and the CV page come from `content/resume.cjs`.

1. Edit `content/resume.cjs` in both languages (no en or em dashes; bullets start with a verb).
2. `node scripts/build-resume.cjs <folder>` writes the application copies (with phone number); add `--web` for the website copies (no phone number).
3. Convert each .docx to PDF (Word: Save as PDF, or `soffice --headless --convert-to pdf`) and put the web copies in `public/cv/` with the same names.
4. `node build.mjs`. The CV page updates by itself.

## Deploying

The output is static files, so any static host works.

**GitHub Pages (current setup):** the site lives at https://jennyhoang-ul.github.io/hennyhoang-ul.github.io/. Upload the contents of `dist/` (not the folder itself) to the root of the repository, including `.nojekyll`. All links are relative, so the `/hennyhoang-ul.github.io/` base path works without changes. `siteUrl` in `site.config.mjs` is already set to this address for `hreflang` and `canonical` links; change it if the repository is renamed.

If you later push the source (not `dist/`) instead, `.github/workflows/pages.yml` builds, checks and publishes on every push to `main` (Settings, Pages, Source: GitHub Actions).

**Netlify or Vercel:** build command `node build.mjs`, output directory `dist`.

## Accessibility and performance

Semantic headings and landmarks, a skip link, visible keyboard focus, 44px touch targets, tables that relabel themselves on phones, reduced motion respected, light theme only (by design). Fonts (Anton, Spectral, Be Vietnam Pro) are self-hosted in `assets/fonts` with Vietnamese subsets, so the site loads no third-party resources.

The visual system (concept, colour tokens, type scale, grid, components) is documented in `DESIGN.md`.
